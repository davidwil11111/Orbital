## Issues

1. **W3 does not protect `.git\config` from git itself (security).** As the worker, `git remote add
   evil …` and `git config --local core.hooksPath foo` both succeeded. Git writes `config.lock` and
   renames it over `config`. The worker has Full Control on `.git\` (inherited from the workspace grant),
   so it can delete/replace the child file whatever the file's own deny says; the replaced file has no
   deny ACE at all. `core.hooksPath` pointing at a worker-writable folder then gives the worker code
   execution as the user on the user's next `git commit`. Renaming `.git\hooks` away is very likely the
   same (the agent declined to try). Before 114 this was masked because git could not read the config at
   all. A deny on the file cannot stop this; it needs `DELETE_CHILD`/`DE` denied on `.git\` itself (or a
   deny on `.git\` for write/add-file plus explicit allows for the paths git must write).
2. **Stale-ACE classifier never reaches "current" on this Windows build.** icacls prints mask `0x116`
   (the new WD,AD,WEA,WA) and `0x100116` (the old `W` with SYNCHRONIZE) both as `(W)` (verified with a
   scratch file). `_classify_deny_ace` compares the printed group, so every check is "stale": every shell
   command runs `/remove:d` then `/deny` on `.git\config` and `.git\hooks` (log line each time), leaving
   a brief window with no deny. The ACE it writes is correct. The unit tests mock icacls printing
   `(DENY)(WD,AD,WEA,WA)` (`tests/unit/test_windows_permissions.py:127`), which this build does not do.
   Reading the mask (e.g. `Get-Acl` / `GetNamedSecurityInfo`) instead of icacls text would fix it.
3. **The Windows denial detector misses PowerShell's wording.** The shell tool wraps every command in
   `powershell -Command`, whose denial is `Access to the path '…' is denied.` (zh: `对路径“…”的访问被拒绝。`).
   Neither contains `access is denied` / `拒绝访问`, so `Set-Content`, `New-Item`, `Get-ChildItem`
   denials raise no `[sandbox]` line, no card and no hands-off parking. Only cmd's `Access is denied.`
   matches. Also: cmd `dir` on a list-denied folder prints `File Not Found` (the agent then told the
   user the file was deleted), and a compound command whose last statement succeeds exits 0, which the
   detector skips. The model habitually appends `; Write-Output "EXITCODE=$LASTEXITCODE"`.
4. **In 需确认 the card never appears for a first-time command.** check_in intercepts every shell
   command; after the user approves, `AgentManager.approve()` runs the tool and stores `result.meta`
   but never checks `meta["sandbox_denial"]` (`agent_os/daemon_v2/agent_manager.py` ~3740–3754). The
   tool output still tells the agent "You may wait for the user's decision on running this outside the
   sandbox", but no decision is offered and the turn ends. The card only appeared once auto-approve
   (10 min) sent the command down the loop path. NOTES item 3 is exactly this path.
5. **更新 can uninstall Claude Code.** `claude update` (npm method) failed after 39 s ("Failed to install
   update"); the npm log stops ~1 s into the download. Afterwards `@anthropic-ai/claude-code` had no
   version and no `claude` shim: the CLI was gone, while the card still said 已安装 v2.1.100 until 刷新.
   A manual `npm i -g …@latest` took 3 min on this network. For npm installs, running npm directly
   with a long timeout (or verifying the binary still exists and saying so) would avoid leaving the user
   with nothing.
6. **Open project and the FOCUS prompt.** With safe mode off, deepseek still refused `whoami`, `ls
   ~/.ssh`, the Desktop and a grep outside the workspace, even with explicit owner consent, citing the
   FOCUS rule (`prompt_builder.py` `_safety`). The prompt is unchanged for open projects, so for this
   model "open" behaves like safe mode. Separately, the `[sandbox]` hint's "reads of credential stores
   are denied" made the model treat an ordinary denied file as a credential and refuse to re-run it or
   repeat an allowed-once result.
7. **"Always allow" keys on the first token.** On Windows that is often `cmd` (`本项目始终允许 cmd`),
   which then allows every `cmd /c …`. `cmd`, `powershell`, `pwsh` probably need the same treatment as
   `sh -c`.
8. **The Windows shell wrapper strips double quotes** (`cmd /c "cd … && powershell -Command "<cmd>"…"`):
   `Write-Output "--- exists? ---"` prints one word per line; `cmd /c "echo x> f"` runs as `echo x=`.
   Probably pre-existing.
9. Smaller: a card raised while Project Settings was open did not render on return to the chat until a
   reload (seen once). Session-start re-grant fails on worker-owned files (`icacls grant failed …
   .git\index: Access is denied`; the user lacks WRITE_DAC on files the worker created). Auth probes
   log WARNINGs every start for agents that are not installed (cursor, kimi). The release build logs
   every WebSocket frame to the console. 监督模式's description ends in "安全模式。", which now collides
   with the switch's name. The Claude Code card said 已登录 with an expired OAuth token.
